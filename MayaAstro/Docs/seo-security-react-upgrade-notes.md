# SEO, Security and React Upgrade Notes

## What changed in this upgrade

- The public site now resolves the active `WebsiteId` from the current request host through the `Site:Websites` configuration list. This keeps the admin panel's multi-domain blog storage compatible with public blog, video and quote pages without hard-coding domain `1` in the front end.
- SEO defaults now live in configuration (`Site`) so each domain can use its own name, canonical base URL and social sharing image.
- `/sitemap.xml` and `/robots.txt` are generated by the ASP.NET Core application. The sitemap includes important static pages, zodiac pages and published blog URLs returned by the existing API.
- Security hardening was added for HTTPS redirection, secure cookies and common browser security headers.
- The tracked development configuration was sanitized. Put real connection strings and API keys in environment variables, deployment secret stores or local user secrets instead of committing them.

## Database impact

No database schema change is required for this upgrade. The existing `WebsiteId` fields continue to drive multi-domain content ownership.

If you need to add another public domain, update configuration only:

```json
"Site": {
  "Websites": [
    {
      "Host": "example.com",
      "WebsiteId": 2,
      "SiteName": "Example Astro",
      "PublicBaseUrl": "https://example.com"
    }
  ]
}
```

## Recommended React direction

For the best Google SEO, keep ASP.NET Core server-rendered pages for public routes or use a React framework that supports server-side rendering/static generation, such as Next.js or Remix. A client-only React single-page app would usually be worse for SEO than the current Razor-rendered public pages.

A safe phased migration is:

1. Keep ASP.NET Core as the backend API and admin host.
2. Move public interactive widgets into React islands only where needed.
3. If a full React front end is required, create a separate SSR React app and have it consume the existing `/api/*` endpoints.
4. Keep `/sitemap.xml`, `/robots.txt`, canonical URLs and structured data on the server-rendered layer.
